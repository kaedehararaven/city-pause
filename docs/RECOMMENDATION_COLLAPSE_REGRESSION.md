# 推荐坍缩与停留时长回归排查

## 已确认的代码原因

1. simple-0.1 的 Pareto 仍消费 activityOpportunity/costFit，未消费 rating/merchant price。活动充分性对可行候选恒定，其他事实常未知，任意小的路线时间差就可能让最近地点淘汰所有其他地点。
2. 地点详情仅在 PlaceDetails 展开后写入组件局部状态，没有传回推荐输入。用户看到评分不意味着引擎也拿到了评分。
3. 引擎把停留限制为 suggestedStayMinutes（REAL 默认15分钟），忽略已有 stayAllocation=flexible。因此60分钟预算、6分钟交通、6分钟缓冲只安排27分钟。
4. normalizeIntent 依赖已停用的搜索 profile，所有活动被归为 flexible。Goal Match 本身仍没有产品确认的等级来源。

## 本次修复

- Pareto 只消费 Goal Match（当前 UNKNOWN）、实际交通秒数、真实评分、数值商户价格。不再用活动充分性或费用偏好作为淘汰维度。
- 共同已知维度必须全部不差且至少一项明确更好才构成支配；任何共同已知的反向优势都保留。单独移动优势沿用产品20%比较线，不因几秒差异淘汰。评分/价格严格比较，不新增容差。UNKNOWN不制造优势，也不屏蔽已知全面劣势。
- 推荐前串行读取已有详情服务，复用展示层的5分钟缓存和同请求去重；失败保持未知，不阻断路线或编造评分。路线参数、时长、坐标、缓存没有修改。
- flexible停留恢复为预算减移动减缓冲；非flexible仍尊重显式建议上限。分配的停留是计划，不是百度建议游览时长，也不参与Pareto质量比较。
- 恢复用户活动意图记录，但不恢复Goal到类别权重。Goal等级仍NOT YET RESOLVED，不保证切换需求按钮就产生不同结果。
- 开发审计增加候选/硬可行/Pareto计数及实际淘汰优势；不包含精确坐标或provider ID。

## 验证与限制

合成回归包括7个相近路线全部保留、评分/价格权衡、UNKNOWN不保护明显劣势、数值价格排序、15/30/45/60分钟灵活停留、固定停留上限、活动意图保留，以及详情进入推荐输入/失败保持未知。

这不是现场复测。真实浏览器和地点审核由用户进行。若实际候选仍全面被一个地点支配，新规则仍允许只返回一个；不添加保底数量或人为复活。地点详情缺失、路线可行候选过少和尚未解决的Goal等级来源仍可能使结果相同。

本文件纠正上一轮报告中“rating/price已参与完整决策”的过早结论；不宣称上一轮架构所有验收项都已完成。
