# Multi-stop补搜、首站回退和公开路线回放

2026-09-28。产品已批准多地点独立补搜，以及默认排名最多3个首站、共享6次新增路线额度。此修订优先于先前文档中“不得补搜”“只免费回退到第2名”的规则。

## 正式链路

单地点原流程与输出不变。单地点先展示；多地点随后运行：

`默认单地点结果 → Family数量检查 → 必要时独立补搜/复用记录 → 已有v3路径验证 → 少量去程验证 → 复用单地点可行性与排序 → 最多3个Anchor → 共用额度验证站间边 → 既定多地点排序/去重`

新增候选只进入多地点副本，不写回单地点Candidate Pool、Map discovery snapshot、原起点或单地点排序。`goalCandidateSupply.ts`仅导出既有路径匹配和导航地点判断函数，没有改S/M/W表或单地点召回行为。

## 独立补搜

- 触发：步行、无需返程、45分钟以上，已通过单地点门禁的Family数量小于当前maxStops。只用于补足体验类型，不保证所有理论可行路线都被搜索到。
- 查询词：当前Goal中属于尚缺Family的既有S/M词合并为一个查询；W永不主动搜索。使用现有Web Search V3适配器，最多3页×20条，不逐标签搜索。
- 真实classified_poi_tag后验证；祖先继承、导航过滤、去重与每完整标签最多5个继续适用，容量与已有候选共享。独立子地点按自身分类验证。
- 不额外调用Detail。缺分类拒绝，搜索报错保留原单地点/原多地点候选，不造标签，不使用关键词或源Goal等级替代事实。
- 搜索结果缓存5分钟、最多8项，key含Goal、canonical origin、搜索范围和关键词；仅显式生成运行，无React effect触发搜索。
- 补充去程验证最多新增2次，且至少留1次额度给站间边。它和站间路线共用同一个6次ledger，失败也计数。已有成功路线/缓存不重复请求。
- 只在补充队列中用Goal等级、起点直线距离、稳定ID进行便宜提案顺序；不把直线距离当路线秒数。每成功补足一个新Family才更新覆盖数，达到maxStops即停。最终重新调用既有单地点可行性和默认排序，不造新综合分。

明确限制：Family数量足够但地理分散，或补搜返回信息仍缺失时，不无限补搜。最多2个冷去程请求可能找不到足够新Family；不会为凑结果超过额度。额外Detail救援、持续追加查询不在本轮范围。

## 首站（历史规则）

此节已由 [独立首站与Demo补采](MULTI_STOP_INDEPENDENT_ANCHORS.md) 替代：前三首站独立构造、每首站最多一条，成功后不停止；下文采集数量和矩阵为本轮修订前的历史记录。

保持默认单地点排名语义；补充地点通过同样可行性/排序后参与多地点候选排名，用户主动价格排序不会改变首站。

按可用候选前3名顺序尝试。每个首站先全池免费预检；预检无解或真实构造未找到合法两站均可换下一名。首次合法路线出现后，不再换其他首站，剩余额度用于完善当前路线。

在某首站尚无合法两站时，为后续首站保留份额：`当前剩余请求数 / 尚余首站数`向下取整，至少允许尝试1次但实际始终受全局ledger限制。缓存边可免费复用。第一名成功后释放预留；最多6个第二站提案、3个两站扩展前缀、每前缀2个第三站的边界仍保留。

没有换首站重置预算，没有自动重复失败边，没有修改Goal/Mobility/Rating/Price、Family、dwell或两站/三站去重。

## 离线Demo采集

新增`src/demo/public-multi-capture.json`，不修改原`public-capture.json`的65个地点和单地点去程事实。

先复用不同Goal原已采集的公开POI并按当前Goal重新验证，探索有效多地点池从culture26拓展为culture26 + commercial1 + bookCafe1。补充候选原起点路线已在旧记录中，因此无需新增去程/地点搜索。

通过现有本机代理，仅公开区域点到点步行路线：实际16次，16条成功；Search0次、Detail0次、用户定位0次、返程0次。脚本限定最多18次、连续3次服务失败即停止，逐条保存adapted Contract，不保存密钥/原始响应。

`scripts/capture-public-multi.mts --plan`只离线检查；`--capture`会消耗真实路线额度，需明确授权后才运行。历史有向边只装入独立replay cache，不作为新鲜实时路线缓存；回放无fetcher，缺边不能联网补算。

## 禁网回放结果

|Goal|120分钟|150分钟|180分钟|
|---|---:|---:|---:|
|休息|1条两站|1条两站|1条两站|
|散步|1条两站|1条两站|1条两站|
|探索|1条两站|1条两站|2条两站|

上述回放新增请求均为0。180分钟采集过程中，休息第1首站失败、第2首站成功，证实有限回退发挥作用。

30分钟仍仅单地点；45/60可能受最低停留约束，90分钟仍有未采集的站间边。本次有界补采不保证全时长完整覆盖。两站仍可胜过三站，不为展示强凑三站或填满预算；停留max和休息maxStops=2均未更改。
