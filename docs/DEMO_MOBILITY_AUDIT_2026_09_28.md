# Demo分类与散步排序核查

本次只用已有真实快照及合成单测，不调用百度接口，不获取用户定位。

## 已证实的Demo分布

|需求|候选分类|60分钟可行数|
|---|---|---|
|歇一会儿|20个咖啡厅|1|
|散散步|16个公园（含城市、遗址、森林、文化等子类）|2|
|逛点新鲜的|14个美术馆、2个私立美术馆、3个艺术馆|3|

其余候选均被travel_gate过滤。休息与探索池确实偏科，不能把55个总候选描述为各需求都丰富。无文字时“随心安排”沿用探索；因此默认结果是艺术场馆，不代表全部池都是场馆。保留真实快照，不添加未经采集的地点、不强行触发M或改变S/M/W。

## Mobility实际职责

无权重、无综合分。先执行硬门槛：不返程最大交通时间=预算×0.3，返程往返总和=预算×0.4。默认排序先S>M>W>UNKNOWN，同等级交通时间差达到20%才先排较短者，否则比较既定评分/价格。

因此可行S公园不能被W咖啡厅仅凭距离压过。公园可能因路线失败、交通超限、明确关闭等在排序前排除；同为S的商业街等没有额外公园优先。用户主动“距离优先”会绕过默认等级顺序，仅重排已有可行结果。此次增加排序选中状态，未更改比较规则。

单测覆盖2分钟W咖啡厅对18分钟S公园：60分钟默认仍公园优先；公园1081秒则在60分钟被Travel Gate拒绝；90分钟恢复且仍优先。未取得用户现场快照，不能断言具体现场属于哪一种原因。

## 时间入口

移除15分钟快捷档和任意分钟输入；保留30/45/60，长时间以30分钟递增选择90/120/150/180。180沿用现有引擎上限。底层仍支持旧15分钟意图，兼容历史记录；未改时间门槛、排序或路线。

离线回放在长预算下只重算现有采集池，不代表重新扩大搜索。60/90/120/150/180分钟可行数分别：休息1/5/8/18/19，散步2/2/2/10/13，探索3/3/6/15/18。
